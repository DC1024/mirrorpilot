# MirrorPilot 镜像领航

> 为你的网络找到最快的容器镜像加速源，并把你拉不动的镜像搬回家。

[English](README.md)

---

## 这是什么

MirrorPilot 是一个**自部署、单二进制的 Web 面板**，用来处理容器镜像的访问问题——尤其是在 `docker.io` 和 `ghcr.io` 又慢又连不上的网络环境里。

它是为一个很具体的前提设计的：**你手上没有任何一台能稳定访问海外仓库的机器。** 这一个约束就否定了最常见的答案（Harbor / Zot 这类 pull-through cache 必须自己能回源），也决定了这个项目其余部分的形态。

## 这不是什么

把边界说清楚，对大家都省事：

- **它不是镜像代理。** 它不在你的拉取链路上，也无法凭空让一个拉不到的镜像变得可拉。
- **它不是 KSpeeder 的替代品。** KSpeeder 是把第三方镜像源聚合到自己一个出口后面；MirrorPilot 做的是测量这些源，并帮你把镜像搬进你自己掌控的仓库。
- **它不会偷偷改你的 `daemon.json`。** 它会生成配置和命令，由你审阅后自己执行。
- **它不是闭源中间件。** 没有付费档位，也不会把免费的公共节点包装成服务卖给你。

> 代理是放大器，不是发电机。上游拿不到的东西，它一样拿不到。

## 测速是怎么做的

每个镜像源都分四步测，测速页会**分别**显示这四步。知道「哪一步挂了」，就是一份有用清单和一片红之间的区别：

1. **连通** —— `GET /v2/`。主机是否活着、是否在说 registry 协议。
2. **取 token** —— 匿名拉取 token 花了多久。去哪里取由 registry 决定，不由我们猜：`/v2/` 那次 401 会带回一个 `WWW-Authenticate` 挑战，token 就去它点名的 realm 换——那个 realm 常常不是镜像源自己的域名。镜像源可以秒回上面那步，却在这一步很慢。
3. **取 manifest** —— 首字节耗时，外加对**实际收到的字节**算一次摘要。
4. **吞吐** —— 实际拉一个 blob，上限 8 MiB。这一项最关键，因为一个镜像源可以秒回却毫无用处。

判定结论时有四条规矩，也正是它比 ping 更值得信的原因：

- **限流不算失败。** 429 说明镜像源活着，只是现在不想跟我们说话，所以它有自己独立的琥珀色结果。把 429 归进「挂了」会让健康镜像源显得是坏的。
- **摘要从不采信对方给的。** blob 摘要一律由本地对收到的字节现算，绝不读响应头。而受 8 MiB 上限截断的读取会被报成**无法校验**，而不是「不匹配」——明明是我们要少了，却去指控镜像源在发坏内容，正好是错的答案。
- **横杠不是零。** 没产出数字的那一层显示横杠。写「0」等于断言它快到时钟都分辨不出来，这和「它压根没跑」是两回事。
- **匿名就是匿名，重定向要按真实 pull 的方式走完。** 探针从不代填用户名密码：registry 不肯给匿名 token，就如实报出来。而跨主机重定向会丢弃 `Authorization` 头，所以遇到用 `302` 应答的镜像源，会拿新的挑战重新授权一次再请求最终的 URL——否则像 `hub.rat.dev` 这种别名源会被判成「需要凭据」，可偏偏 `docker pull` 拉它是通的。

每次测速都会记下 manifest 解析到的摘要，所以同一批测出来的镜像源可以诚实对比——tag 可能命中的是缓存，同一个 tag 在两个镜像源上未必是同一份字节。

这一切都不依赖你记得去点那个按钮。每隔 `probe.interval`，面板会自己把这套四层测量对全部已启用的镜像源重跑一遍，这正是配置页上的排名不会悄悄变成「上个月排名」的原因。有两件事值得知道：后台测速**不需要任何凭据**，所以面板处于锁定状态时它照样在跑；以及 `interval: 0s` 可以把它关掉——这些测量是从本进程所在的网络发出的，不是所有人都愿意把这份流量打在别人运营的镜像源上。

## 把拉不动的镜像弄回家

测速回答的是「哪个镜像源最快」，它不回答「这个镜像到底怎么拉下来」。有三页负责后者，它们分开存在，是因为障碍的形状随镜像所在的位置而变：

**配置（`/config`）**——给 Docker Hub 上的镜像用。它把你已启用、已测过的镜像源排好序，再按这个顺序生成 `daemon.json`（或 containerd 的 `hosts.toml`）。有两处细节值得知道：

- **顺序本身就是功能。** Docker 会按次序逐个尝试，遇到第一个能应答的就停下，所以一个排在第二位的快源，价值不比一个慢源高。
- 把你现有的 `daemon.json` 粘进去，它是**合并**而不是覆盖：`registry-mirrors` 整段换掉，`insecure-registries` 合进去，不由它管理的设置原样带过。带注释或末尾逗号的文档会被**拒绝**，而不是被悄悄修正——Docker 同样不接受这两样，假装能修，只会给你一份之后在更不显眼的地方失败的配置。

它也会说明自己**做不到**什么：`registry-mirrors` 只对 Docker Hub 生效，所以代理其他仓库的已启用源会被计数并排除，而不是写进去占一个实际不起作用的位子。

**搬运（`/sync`）**——给 `ghcr.io`、`quay.io`、`gcr.io` 这类镜像用，这些仓库没有任何镜像源能帮上忙。这就是「借别人的网络」那条路：GitHub Actions 的运行器能访问你机器访问不了的仓库。这一页生成工作流、把需要的凭据存成仓库密钥，并且可以用一串镜像地址触发一次运行。「接口接受了」和「复制成功了」是两回事——GitHub 收了请求之后就不再说话——所以页面给你看的是运行记录，而不是在按钮上写「成功」。

**中转（`/config` 下半部分）**——可选，在你设置地址之前一直关着。中转站不是镜像源，区别在地址形状上：镜像源在上游同样的路径上接收仓库协议，而中转站把**完整原始地址当作路径**，由它自己去决定去哪儿取。示例用的是华为云 SWR 的公共 `ddn-k8s` 中转。设一次地址，这一页就能把任何镜像地址变成一条拉取命令。

这三页都不会动你的系统。它们只生成文本，怎么用由你决定。

## 快速开始

```bash
git clone https://github.com/DC1024/mirrorpilot.git
cd mirrorpilot
docker compose up -d
```

然后打开 `http://<主机>:8080`。首次访问会让你创建面板账号——没有默认密码，也不会预先往磁盘上写任何东西。

> **不要把面板暴露到公网。** 它是用来保存你 GitHub 和阿里云凭据的。请放在内网，或挂在一个负责 TLS 的反向代理后面。

## 密码是怎么工作的

这是唯一一处值得在托付令牌之前读完的设计。

你的密码干两件事：

1. **用来登录。** 磁盘上只存它的 Argon2id 哈希，不存密码本身。
2. **派生出加密密钥**，保护你之后保存的第三方凭据。数据库旁边存一个随机盐，密钥由「密码 + 盐」派生。

派生出来的密钥**只存在于进程内存**。这带来一个你会注意到的结果：容器重启后面板仍是登录状态（会话 cookie 还在，因为会话本身就是数据库里的行），但在你输入一次密码之前，它读不出任何一条已保存的凭据。重启后只有第一次请求会要密码。

这是刻意的。把密钥的生命周期绑在浏览器会话上，意味着你一关标签页，后台的测速和定时搬运就停了。密钥随进程存活，会话是另一件更短命的东西。

**忘记密码，已保存的凭据就找不回来了。** 没有重置链接，也没有恢复密钥。这正是它有意义的地方：也正因如此，一个被偷走的 `/data` 卷本身毫无用处。

你能做的是**推倒重来**。带 `-reset` 参数启动面板，会在一个事务里删掉账号、所有会话和全部已保存的凭据，然后退出——它什么都恢复不了，只是把路清出来，好重新走一遍首次初始化。你的镜像源、设置和测速历史都会留着，因为它们本来就不属于机密。这就是「我丢了密码」和「我丢了数据」的区别：前者只是麻烦，后者才是这套加密要防的事。

## 配置

优先级由低到高：内置默认值 → `config.yaml` → 环境变量 → 命令行参数。

```yaml
# /data/config.yaml
listen: 0.0.0.0:8080
data_dir: /data
log_level: info          # debug | info | warn | error

# 当反向代理替你终止 TLS 时，把它设成对外可见的 HTTPS 地址。
# 面板据此把 cookie 标为 Secure。如果你是在内网用明文 HTTP 直连面板，
# 请留空——否则浏览器会静默丢弃会话 cookie，表现得很像「密码错了」。
base_url: ""

probe:
  concurrency: 5         # 同时测几个源，1..16
  timeout: 15s           # 每个请求的时限
  interval: 30m          # 后台自动测速间隔：最小 1m，写 0s 表示关闭
```

| 参数 | 环境变量 | 含义 |
|---|---|---|
| `-config` | `MIRRORPILOT_CONFIG` | 配置文件路径（默认 `<数据目录>/config.yaml`） |
| `-data` | `MIRRORPILOT_DATA` | 持久化数据目录（默认 `/data`） |
| `-listen` | `MIRRORPILOT_BIND` | 监听地址（默认 `0.0.0.0:8080`） |
| `-reset` | — | 删除账号、会话与已保存凭据后退出（推倒重来；不恢复任何东西） |
| — | `MIRRORPILOT_LOG_LEVEL` | 日志级别 |
| — | `MIRRORPILOT_BASE_URL` | 对外可见地址 |

## 给面板套上 TLS

面板自己只说明文 HTTP，只监听一个端口，不负责 TLS。如果你需要在局域网之外访问它，就在前面挂一层反向代理。Caddy 是最短的路，因为证书它自己管。

改动有三处：

1. **不要再发布面板的端口。** 让代理通过 Docker 网络访问它，这样除了走 TLS，没有别的路径能碰到面板。
2. **把 `MIRRORPILOT_BASE_URL` 设成对外的 HTTPS 地址。** 面板据此把会话 cookie 标成 `Secure`。不设的话浏览器会静默丢弃 cookie，表现得很像「密码输错了」。
3. **`/data` 的挂载保持原样。** 整个过程不碰数据库。

如果你**没有域名**、只有一个 IP 地址（家庭和小型办公环境的常态），有两个证书细节必须知道：

- **Let's Encrypt 需要一个名字才能验证。** 纯 IP 上它不可能成功：HTTP-01 挑战会被占用这个地址的人应答，而不是你的服务器；TLS-ALPN-01 则在传输途中被重置。`tls internal` 让 Caddy 改用自家 CA 签发。链路仍然是加密的，只是浏览器会提示一次「无法确认对端身份」——在这个场景下，这个提示是诚实的答案，不是需要掩盖的配置错误。
- **`default_sni` 不能省。** RFC 6066 禁止客户端对 IP 字面量发送 SNI，所以浏览器访问 `https://203.0.113.10/` 时带的是空服务器名，而 Caddy 是按 SNI 匹配站点块的。不设默认值，握手会以 `tlsv1 alert internal error` 收场：证书就在那儿，但没人认领它。判断方法很直接——`curl -k https://203.0.113.10/healthz` 失败，而 `openssl s_client -connect 203.0.113.10:443 -servername 203.0.113.10` 却能正常出示证书。

一份面向「只有地址、没有名字」的 Caddyfile，已在 Caddy 2.11 上验证：

```
{
	default_sni 118.89.25.55
}

118.89.25.55 {
	tls internal
	encode gzip
	reverse_proxy mirrorpilot:8080
}

# 明文进来的请求一律送到加密地址。8080 继续应答，正是为了这个：
# 它曾是面板的地址，留一条跳转，旧书签会响亮地失败，而不是无声地失联。
:80 {
	redir https://118.89.25.55{uri} permanent
}

:8080 {
	redir https://118.89.25.55{uri} permanent
}
```

把它只读挂进 `caddy:2`，80/443/8080 由代理发布而不是由面板发布，再给 Caddy 一个 `/data` 卷，让它的 CA 在重启后还在。记得把 `118.89.25.55` 换成你自己的地址——四处都要换。

## 数据与备份

所有持久化内容都在 `/data` 下：

```
/data/config.yaml      非敏感配置
/data/app.db           SQLite 数据库：账号、会话、加密后的凭据
```

备份就是拷贝这一个目录。迁移就是把它丢到新机器上。数据库离开密码毫无用处——见上文。
